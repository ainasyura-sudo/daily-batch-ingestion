# Gold Data Model

The analytical database is SQL Server. All model tables belong to the
`gold` schema.

## Relationships

`gold.fact_exchange_rate` references:

- `gold.dim_date` through `date_id`.
- `gold.dim_currency` through `base_currency_id`.
- `gold.dim_currency` through `quote_currency_id`.

The currency dimension serves two roles: base currency and quote currency.

## gold.dim_date

Purpose: provide calendar attributes for filtering and grouping exchange rates.

Grain: one row per calendar date represented in the loaded data.

All columns are NOT NULL.

| Column | SQL type | Meaning |
| --- | --- | --- |
| `date_id` | `INT` | Primary key in YYYYMMDD format |
| `rate_date` | `DATE` | Exchange-rate date |
| `year` | `SMALLINT` | Calendar year |
| `quarter` | `TINYINT` | Quarter, 1–4 |
| `month` | `TINYINT` | Month, 1–12 |
| `month_name` | `VARCHAR(9)` | English month name |
| `day` | `TINYINT` | Day of month |
| `day_of_week` | `TINYINT` | 1 = Sunday through 7 = Saturday |
| `day_name` | `VARCHAR(9)` | English weekday name |
| `is_weekend` | `BIT` | 1 for Saturday/Sunday; otherwise 0 |

Keys and indexes:

- `pk_dim_date`: clustered primary key on `date_id`.
- `uq_dim_date_rate_date`: unique constraint on `rate_date`,
  backed by a unique index.
- No foreign keys.

Calendar attributes are generated by the Python Gold loader.

## gold.dim_currency

Purpose: provide currency codes and readable currency names.

Grain: one row per currency code.

All columns are NOT NULL.

| Column | SQL type | Meaning |
| --- | --- | --- |
| `currency_id` | `SMALLINT IDENTITY(1,1)` | Generated surrogate primary key |
| `currency_code` | `CHAR(3)` | Three-character currency code |
| `currency_name` | `VARCHAR(60)` | Readable currency name |

Keys and indexes:

- `pk_dim_currency`: clustered primary key on `currency_id`.
- `uq_dim_currency_code`: unique constraint on `currency_code`,
  backed by a unique index.
- No foreign keys.

The seed script includes USD, EUR, GBP and MYR.

## gold.fact_exchange_rate

Purpose: store daily exchange rates and their inverse values.

Grain: one row per date, base currency and quote currency.

All columns are NOT NULL.

| Column | SQL type | Meaning |
| --- | --- | --- |
| `rate_id` | `INT IDENTITY(1,1)` | Generated surrogate primary key |
| `date_id` | `INT` | Foreign key to `dim_date.date_id` |
| `base_currency_id` | `SMALLINT` | Foreign key to `dim_currency.currency_id` |
| `quote_currency_id` | `SMALLINT` | Foreign key to `dim_currency.currency_id` |
| `exchange_rate` | `DECIMAL(18,6)` | Quote-currency units per one base-currency unit |
| `inverse_rate` | `DECIMAL(18,6)` | Reciprocal of the exchange rate: 1 / rate |
| `loaded_at_utc` | `DATETIME2(0)` | Insertion timestamp; defaults to `SYSUTCDATETIME()` |

Keys:

- `pk_fact_exchange_rate`: clustered primary key on `rate_id`.
- `fk_fact_date`: `date_id` references `gold.dim_date(date_id)`.
- `fk_fact_base_currency`: `base_currency_id` references
  `gold.dim_currency(currency_id)`.
- `fk_fact_quote_currency`: `quote_currency_id` references
  `gold.dim_currency(currency_id)`.
- `uq_fact_date_base_quote`: unique constraint on
  `(date_id, base_currency_id, quote_currency_id)`.

Indexes:

| Index | Key columns | Included columns | Purpose |
| --- | --- | --- | --- |
| `pk_fact_exchange_rate` | `rate_id` | — | Clustered primary-key access |
| `uq_fact_date_base_quote` | `date_id`, `base_currency_id`, `quote_currency_id` | — | Enforce unique business keys |
| `ix_fact_date_id` | `date_id` | `base_currency_id`, `quote_currency_id`, `exchange_rate` | Support date filtering |
| `ix_fact_quote_currency` | `quote_currency_id`, `date_id` | `base_currency_id`, `exchange_rate`, `inverse_rate` | Support currency and date queries |

Rates are stored to six decimal places. Derived inverse values therefore
have the precision defined by `DECIMAL(18,6)`.

## Loading and Reruns

Dimensions are loaded before facts to satisfy foreign-key relationships.

The loader uses SQL MERGE statements to insert missing records.
Existing facts are skipped using the unique business key.

Gold retains the first loaded exchange rate. Revised API values do not
update existing facts during a rerun.

The load commits on success and rolls back on failure.

The SQL schema script creates missing tables. It does not migrate the
structure of tables that already exist.

## Analytics Views

- `gold.vw_fx_daily`: joins facts with calendar and currency attributes.
- `gold.vw_fx_monthly_avg`: groups loaded observations by year, month,
  base currency and quote currency, with average, minimum and maximum rates.

Monthly summaries reflect loaded observations, which may represent only
part of a month.
